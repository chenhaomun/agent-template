# Mobile Sprint Points

Estimate mobile complexity, effort, and uncertainty—not exact hours or lines of code. Use inspected scope, existing components, API readiness, and validation needs. These anchors guide judgment; they are not automatic scores.

| Points | Mobile scope |
|---|---|
| 1 | Spacing, labels, or a minor UI fix |
| 2 | Small page/component change or simple API integration |
| 3 | Simple screen with API integration and basic validation |
| 5 | Multi-step screen, modal interactions, or API with offline handling |
| 8 | Complex flow, deep navigation, multiple APIs, or heavy UI |
| 13 | Multi-screen feature with animations and multi-step logic |
| 21 | Too large or uncertain; split into smaller testable stories before approval |

Use mobile effort for mobile stories; do not add backend/web estimates. Where an existing cross-team parent needs planning points, use the highest discipline estimate rather than summing. Do not create subtasks or change the related-task workflow for estimation. QA is covered through feature complexity, without a separate additive score.
